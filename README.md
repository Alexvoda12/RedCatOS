# RedCatOS — репозиторий автообновления

Этот репозиторий — то, откуда RedCatOS забирает обновления. Формат
намеренно тривиальный (docs §16 «Автообновление»):

| файл       | что это                                                        |
|------------|----------------------------------------------------------------|
| `VERSION`  | версия дистрибутива одной строкой, например `26`               |
| `MANIFEST` | по строке на файл: `<sha256> <размер> <путь>`                  |
| `files/…`  | сами файлы; пути повторяют корень ФС гостя (`files/bin/sh`)    |
| `REMOVE`   | по строке на путь, который пакет просит УДАЛИТЬ (опционален)   |

Как ОС обновляется (команда `sysupdate`, версия текущая: 31):

1. качает `VERSION`, сравнивает со своей `/etc/version` — совпали,
   значит, обновлять нечего (проверка идёт при каждой загрузке, если
   в `/etc/update.conf` стоит `auto yes`);
2. различилось — качает `MANIFEST`, сравнивает sha256 всех файлов и
   отбирает только отличающиеся;
3. отличающиеся скачивает во временный каталог, сверяет хэш каждого
   и только после этого записывает на место. Битый кусок обрывает
   обновление до того, как записан хоть один целевой файл;
4. если в пакете был `files/boot/kernel.bin` — образ ядра применяется
   к загрузочной области самой системой (запись тела → сверка чтением
   → заголовок последним). Вступает в силу после перезагрузки;
5. в самом конце удаляются пути из `REMOVE`, если он есть: такие файлы
   ещё существуют локально, а пакет считает, что их быть не должно
   (выведенные из дистрибутива команды). Удаление — после файлов и
   ядра, поэтому прерывание просто оставит лишний файл, который
   удалит любой следующий запуск `sysupdate` — даже когда версии
   уже равны.

Чего обновление не трогает никогда: сам `/etc/update.conf` (иначе
система потеряла бы адрес своего репозитория) и учётные записи
(`/etc/passwd`, `/etc/shadow`, `/etc/rudoers`). Эти пути не могут
стоять и в `REMOVE` — собрать такой пакет mkupdate откажется.
Загрузчик (`boot.bin`, `stage2.bin`) тоже не обновляется — его перезапись
без резервной копии опаснее ядра; новое ядро и загрузчик по-прежнему
приходят только вместе с новым ISO.

## Как пересобрать и запушить пакет

Из дерева исходников RedCatOS:

```sh
make update-bundle UPDATE_DIR=~/redcatos-updates   # этот каталог — клон
cd ~/redcatos-updates
git add -A && git commit -m "update: версия N"
git push
```

`make update-bundle` кладёт в `UPDATE_DIR` только VERSION, MANIFEST,
REMOVE (когда есть), README.md и `files/` — остальное (включая `.git`)
не трогает.
