# RedCatOS — репозиторий автообновления

Этот репозиторий — то, откуда RedCatOS забирает обновления. Формат
намеренно тривиальный (docs §16 «Автообновление»):

| файл       | что это                                                        |
|------------|----------------------------------------------------------------|
| `VERSION`  | версия дистрибутива одной строкой, например `19`               |
| `MANIFEST` | по строке на файл: `<sha256> <размер> <путь>`                  |
| `files/…`  | сами файлы; пути повторяют корень ФС гостя (`files/bin/sh`)    |

Как ОС обновляется (команда `sysupdate`, версия текущая: 19):

1. качает `VERSION`, сравнивает со своей `/etc/version` — совпали,
   значит, обновлять нечего (проверка идёт при каждой загрузке, если
   в `/etc/update.conf` стоит `auto yes`);
2. различилось — качает `MANIFEST`, сравнивает sha256 всех файлов и
   отбирает только отличающиеся;
3. отличающиеся скачивает во временный каталог, сверяет хэш каждого
   и только после этого записывает на место. Битый кусок обрывает
   обновление до того, как записан хоть один целевой файл.

Чего обновление не трогает никогда: сам `/etc/update.conf` (иначе
система потеряла бы адрес своего репозитория), учётные записи
(`/etc/passwd`, `/etc/shadow`, `/etc/rudoers`), а также ядро и
загрузчик — они не лежат в файловой системе, новое ядро = новый образ.

## Как пересобрать и запушить пакет

Из дерева исходников RedCatOS:

```sh
make update-bundle UPDATE_DIR=~/redcatos-updates   # этот каталог — клон
cd ~/redcatos-updates
git add -A && git commit -m "update: версия N"
git push
```

`make update-bundle` кладёт в `UPDATE_DIR` только VERSION, MANIFEST,
README.md и `files/` — остальное (включая `.git`) не трогает.
